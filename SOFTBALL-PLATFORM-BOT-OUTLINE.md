# Region Softball Platform — Bot Working Outline
Version: 2026-09-14
Audience: Grok bots + Claude. Humans do not write HTML or SQL.
Status: Ready to execute Phase 0–1.

---

## 0. Mission (read this first)

Build one region softball website with three layers:

1. Public region hub
2. Team subsites (season stat books, login required)
3. Tournament subsites (one event, unique login)

Backend: PocketBase (SQLite + auth + file uploads + REST API).
Frontend: pages generated by Claude or Grok. No hand-written code from the owner.
Stats ingest: Grok bots read GameChanger box scores / screenshots and write SQLite.
Tournament ingest: Grok bots scrape or read dropped box scores and update standings, brackets, leaderboards.

Owner approves staged stats before they go live.

---

## 1. Non-negotiable rules for every bot

- Do not invent player stats. If a cell is unreadable, flag it. Do not guess.
- Player identity key is standardized name: `Firstname LastInitial #jersey` (example: `Evelynn M #17`). Never key off batting-order row.
- IP thirds: `.1` = 1/3 inning, `.2` = 2/3. Sum IP in outs, then convert.
- Youth ERA = `(ER * 7) / IP` when IP > 0, two decimals.
- BA = `H / AB` when AB > 0, three decimals (`.312`). Else `.000`.
- Contact% = `(AB - SO) / AB * 100` when AB > 0, one decimal.
- Strike% = `Strikes / Pitches * 100` when Pitches > 0, one decimal.
- Never double-count a game. Dedup key: `team_id + date + opponent + score`.
- Raw game rows are append-only. Rollups live in views or a rebuild step.
- New game stats land in `staging_*` tables until status = `approved`.
- Public hub shows only public fields. Team books and event admin stay behind login.
- Do not publish family emails, addresses, or birthdates on public pages.
- If the owner has not answered a decision, use the Phase 1 default in section 11.

## 5. PocketBase collections

Create these exact names. Use slug fields lowercase-hyphen.

### Region
- `orgs` — name, slug, season_label
- `users` — PocketBase auth users + role
- `fields` — name, address, surface, lights, notes, status (open/closed/wet)
- `posts` — title, body, published_at, public (bool)
- `inquiries` — name, email, kind (team/td/other), message, created
- `seasons` — label (2026 Summer), start, end, org

### Team book
- `teams` — name, slug, age_group (10U/12U/14U), season, coach_name, public_record_wins, public_record_losses, logo
- `players` — team, display_name, name_key, jersey, positions, bats, throws, grad_year, active
- `team_games` — team, date, opponent, us_runs, them_runs, result (W/L/T), source (gc/manual), status (staged/approved/rejected), source_ref
- `hitting_game` — game, player, ab, r, h, rbi, bb, so, extra_notes
- `pitching_game` — game, player, ip_outs (integer outs), h, r, er, bb, so, pitches, strikes
- `staging_games` — raw payload JSON, image file refs, parser_notes, status

### Event book
- `events` — name, slug, start, end, venue, ages, public, status (draft/live/archived)
- `event_teams` — event, name, slug, seed, pool
- `event_players` — event_team, name_key, jersey, roster_locked
- `pools` — event, name, tiebreak_notes
- `bracket_games` — event, round, slot, home_team, away_team, home_runs, away_runs, winner, status
- `event_schedule` — event, date, time, field, home, away, status (scheduled/live/final)
- `event_boxes` — schedule_row, hitting JSON or child rows, pitching JSON or child rows, source
- `event_hitting` / `event_pitching` — same grain as team book, scoped to event

API rules:
- Public list: teams (name, slug, age, W-L), events (public), fields, published posts.
- Team book rows: only `team_coach` for that team, `region_admin`, or `bot` writing staging.
- Event admin: `event_td` for that event + `region_admin`.

## 6. Derived metrics (compute on read or rebuild)

Hitting season row per player:
- sums of AB R H RBI BB SO
- BA, Contact%

Pitching season row per player:
- IP display from `ip_outs / 3` with softball notation
- ERA, Strike% if pitches present

Team record:
- count approved `team_games` W / L / T

Event standings per pool:
- W, L, RS, RA, run diff
- Tiebreak order default: W-L, then head-to-head, then RA, then RS. Confirm with TD before first event.

Leaderboard gates default:
- Hitting leaders: min 8 AB for a 2-day event (adjust per event)
- Pitching leaders: min 3.0 IP

## 7. GameChanger ingest spec (team bot)

Input (any one):
- Screenshot(s) of GC hitting + pitching
- Desktop GC box
- Pasted text table
- Later: exported CSV if available

Extract:
- Primary team name, opponent, final score, date if visible
- Hitting per player: name, #, pos if shown, AB R H RBI BB SO
- Pitching per player: name, IP, H R ER BB SO, Pitches-Strikes if shown
- Game result for primary team

QC:
- Headers first, then name, then numbers by column position
- Watch mobile column shift
- 10U ranges: AB 0–6 typical; H ≤ AB; IP like 4.0 / 2.1 / 0.2
- If alignment is bad, list both possible mappings and set status `needs_review`

Write:
1. Insert `staging_games` with raw JSON + image files + notes
2. Preview table in `/teams/{slug}/admin/review`
3. On Approve: copy into `team_games`, `hitting_game`, `pitching_game`; rebuild season views
4. On Reject: keep raw, mark rejected, do not touch live book

Name matching:
- Fuzzy-match incoming name + number to `players.name_key`
- If no match, create a `needs_player_link` flag. Do not silently create a second player.

## 8. Tournament ingest spec (event bot)

Input:
- Public box / GameChanger link
- Photo of book
- TD typed final score (standings only, no box)

On each final:
1. Write `event_schedule` status = final + scores
2. Write box rows if present
3. Recompute pool table
4. Advance bracket winner into next slot
5. Rebuild leaders with gates
6. Do not unlock a frozen roster

If only a final score exists, update standings/bracket but leave leaders unchanged and note “no box.”

## 9. What each bot is allowed to do

### Bot A — Team Stat Ingest
Trigger: new image or text dropped for a team.
Actions: parse, stage, notify coach “review game vs X.”
Forbidden: approve its own work; delete approved rows.

### Bot B — Team Publisher
Trigger: after Approve, or weekly Sunday 8pm ET.
Actions: refresh hitting/pitching tables, update public W-L on hub card, draft a 4-sentence recap into `posts` as unpublished.

### Bot C — Tournament Board
Trigger: during event window, every time a box or score arrives.
Actions: scores, standings, bracket, leaders.
Forbidden: change rules text or locked rosters.

### Bot D — Hub Editor
Trigger: owner prompt or after Bot B recap.
Actions: draft news, field-closed note, this-weekend blurb.
Forbidden: publish without owner say-so in Phase 1.

### Claude (or Grok page bot)
Trigger: owner says “build pages.”
Actions: generate PocketBase collections, HTML/JS pages that call PocketBase, mobile-friendly tables, login screens.
Forbidden: change metric formulas in section 1.
